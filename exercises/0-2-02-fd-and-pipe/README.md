# 0-2-02. ファイルディスクリプタ（FD）とパイプの正体

この節では、Linuxの根底にある **「すべてはファイルである」** という哲学の核心である **ファイルディスクリプタ（File Descriptor: FD）** と、コマンド間を直結する **パイプ `|` の物理的な仕組み** をハンズオンで解明しました。

---

## 1. ファイルディスクリプタ（FD）の基礎

OS（カーネル）は、プロセスが入出力を行う際の「接続口（整理番号）」として整数を割り当てます。

| FD番号 | 名前 | デフォルトの接続先 | 説明 |
| :---: | :--- | :--- | :--- |
| **`0`** | 標準入力 (stdin) | `/dev/pts/X` (キーボード/擬似端末) | 入力を受け取る窓口 |
| **`1`** | 標準出力 (stdout) | `/dev/pts/X` (ターミナル画面) | 正常な出力を書き込む窓口 |
| **`2`** | 標準エラー出力 (stderr) | `/dev/pts/X` (ターミナル画面) | エラーやログを書き込む窓口 |

> **「すべてはファイルである」原則**：
> キーボード入力も画面表示も、Linuxカーネルにとっては `/dev/pts/X` というスペシャルファイルに対する `read` / `write` に過ぎません。

## 2. リダイレクトによるFD差し替え (`01_fd_redirection.sh`)

### 原理
リダイレクト記号 `>` を使うと、プログラム本体（`echo` や `sleep`）には一切手を加えず、シェルが起動時に **FD 1 の接続先を画面からファイルへと切り替えます**。

```text
通常時:         [プロセス] --- FD 1 (l-wx) ---> /dev/pts/1 (画面)
リダイレクト時: [プロセス] --- FD 1 (l-wx) ---> /tmp/stdout_test.txt (ファイル)
```

### 実験で得られた重要な知見
1. **非対話バックグラウンド実行（`&`）の安全装置**:
   - スクリプト内でコマンドをバックグラウンド実行すると、**FD 0（標準入力）が自動的に `/dev/null` に接続される**（裏のプロセスがキーボード入力を横取りするのを防ぐPOSIX/Bash仕様）。
2. **プロセス生成とリダイレクト設定の順序**:
   - `fork`（プロセスの複製）が行われた直後、一瞬の隙間を経て `dup2`（FDの差し替え）が行われる。スクリプトでFDを直後に観察する際は微小な待機（`sleep 0.1`）が必要となる。

## 3. パイプ `|` の物理的配線 (`01_fd_redirection.sh`)

### 原理
`cmd1 | cmd2` を実行したとき、カーネルはメモリ上に匿名パイプ（`pipe:[ID]`）を開設し、前後のプロセスのFDを直結します。

```text
[cmd1 (PID 112)] --- FD 1 (書き込み) ---> pipe:[719] ---> FD 0 (読み取り) ---> [cmd2 (PID 113)]
```

### 実験結果
```text
PID 112 のFD:
  1 -> 'pipe:[719]' (l-wx: 書き込み専用)
PID 113 のFD:
  0 -> 'pipe:[719]' (lr-x: 読み取り専用)
```
両者がまったく同じパイプID（`pipe:[719]`）を指していることが確認できます。

## 4. 実務の最頻出バグ：パイプラインと変数の消失 (`02_pipeline_subshell_pitfall.sh`)

### 罠：なぜ `cat file | while read line` でカウントした変数が消えるのか？
- **原因**：Linuxのパイプ `|` は、**右辺のコマンドを別プロセス（サブシェル / fork）として実行する** ため。
- ループ内で更新された変数は子プロセスのメモリ空間にしか存在せず、ループ終了（子プロセス終了）とともに親環境から消滅してしまいます。

```text
[メインシェル] (count=0)
     |
    fork (パイプ右辺)
     v
[サブシェル] (count=1 -> 2 -> 3) ---> ループ終了で消滅！
     v
[メインシェル] (count=0 のまま！)
```

### ★実務の解決策：プロセス置換 `< <(...)`
```bash
count=0
while IFS= read -r line; do
    count=$((count + 1))
done < <(printf "apple\nbanana\norange\n")
echo "Count: $count"  # 3 が保持される！
```
- **理由**：`while` ループ自体は **メインシェル（カレントプロセス）** で実行され、入力データだけを別プロセス `<(...)` から標準入力（FD 0）に流し込むため、変数がメインシェル側に確実に残ります。

## 5. 実務必須イディオム：`while IFS= read -r line; do ... done`

| 要素 | 役割 | ない場合に起きる事故 |
| :--- | :--- | :--- |
| **`while <cmd>; do`** | コマンドの終了ステータスが0（成功）の間ループする | `;` を忘れると文法エラー |
| **`read line`** | 標準入力（FD 0）から1行読み込んで変数に格納する | 入力がEOFに達すると自動でループ終了 |
| **`-r` (raw mode)** | バックスラッシュ `\` のエスケープ解釈を無効化する | パス等の `\` が勝手に消えてデータ破損 |
| **`IFS=`** | フィールド区切り文字を空にする | 行頭や行末のスペース・インデントが勝手に消される（trim） |
