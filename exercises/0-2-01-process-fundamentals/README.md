# 0-2. Linux OSの原理とプロセスの仕組み

この節では、Linuxの根底にある「プロセス生成のメカニズム（`fork` & `exec`）」と、シェルスクリプトやCI環境で頻出する「サブシェルとカレントシェルの挙動の違い」をハンズオンを通して理解します。

---

## 1. プロセスの親子関係とツリー構造 (`01_process_tree.sh`)

### 原理
- Linuxでは、OS起動時に最初のプロセス（PID 1）が立ち上がり、以降のすべてのプロセスは **「親プロセスが子プロセスを複製（fork）し、新しいプログラムに置き換える（exec）」** ことで起動します。
- すべてのプロセスは固有の **PID（Process ID）** と、自分を生み出した親を指す **PPID（Parent Process ID）** を持ちます。

### 実験結果
```text
--- 自身のプロセスID ---
59

--- 親プロセスのプロセスID ---
24

--- プロセスツリー ---
UID          PID    PPID  C STIME TTY          TIME CMD
root          24       0  0 14:45 pts/1    00:00:00 bash
root          59      24  0 15:03 pts/1    00:00:00  \_ bash ./exercises/0-2-process-fundamentals/01_process_tree.sh
root          60      59  0 15:03 pts/1    00:00:00      \_ ps -ef --forest
```

### ポイント
1. **スクリプト実行による子プロセスの生成**:
   - 端末で操作しているBash（PID 24）が親（PPID）となり、スクリプト実行用のBash（PID 59）を子として生成。
   - スクリプト内の `ps` コマンド（PID 60）はさらにその子プロセスとして実行され、3階層のツリーが形成される。
2. **安全性の原則（副作用の非伝播）**:
   - 子プロセス側で環境変数を変えたりディレクトリを移動しても、プロセス空間が分離されているため親プロセス（端末のBash）には影響を及ぼさない。

## 2. カレントシェル `{ }` と サブシェル `( )` の違い (`02_subshell_vs_current.sh`)

どちらも複数のコマンドをグループ化して実行しますが、**「OSのプロセスとして何が起きているか」** が決定的に異なります。

| 構文 | 実行場所 | プロセス生成 | 変数スコープ | 用途・実務での活用 |
| :--- | :--- | :--- | :--- | :--- |
| **カレントシェル `{ ...; }`** | 現在のプロセス内 | **なし**（同一プロセス） | **共有される**（親に反映） | 複数コマンドの出力リダイレクト、変数を保持したい処理を束ねる |
| **サブシェル `( ... )`** | 複製された子プロセス | **あり**（`fork` される） | **独立**（親に影響しない） | 一時的な `cd` 移動、副作用を外に漏らしたくない処理の隔離 |

### 実験結果
```text
--- 変数のスコープ比較 ---
VAR is original
VAR is changed_by_current
VAR2 is var-2
VAR is changed_by_current
VAR2 is var-2
VAR is changed_by_subshell
VAR is changed_by_current

 --- カレントディレクトリ移動（cd）の副作用比較 ---
Outside: /workspace
Inside: /tmp
Outside: /workspace

--- プロセスIDの正体（$$ vs $BASHPID） ---
親シェル: PID=42, BASHPID=42
サブシェル: PID=42, BASHPID=48
```

### 実務での重要イディオム
1. **安全なディレクトリ移動**:
   - `( cd /path/to/dir && make build )` のようにサブシェルで実行すると、処理完了後に自動的に元のディレクトリに戻るため、`cd` の戻し忘れによる誤動作（意図しない場所でのファイル削除など）を防止できる。
2. **`$$` と `$BASHPID` の罠**:
   - `$$` は「スクリプト起動時のメインプロセスのPID」を保持し続ける。
   - サブシェル内で「本当に動いているプロセスのPID」を取得したい場合は、Bash組み込みの **`$BASHPID`** を参照する。
