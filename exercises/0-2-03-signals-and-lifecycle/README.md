# 0-2-03. シグナルとプロセスのライフサイクル

この節では、Linuxにおける非同期通知メカニズムである **シグナル（Signal）** の挙動、Graceful Shutdownの原理、および実務で頻出する **ゾンビプロセス（Zombie）** と **孤児プロセス（Orphan）** のライフサイクルをハンズオンで解明しました。

---

## 1. シグナルの基礎と主要シグナル

シグナルとは、OSカーネルや他のプロセスから送られる「非同期の割り込み通知」です。

| シグナル名 | 番号 | デフォルト動作 | トラップ可否 | 主な用途・意味 |
| :--- | :---: | :--- | :---: | :--- |
| **`SIGTERM`** | **15** | 終了 | **可** | 通常の終了要求（Graceful Shutdown用、`docker stop`） |
| **`SIGKILL`** | **9** | 強制終了 | **不可（絶対即死）** | カーネルによる強制抹消（`docker kill`、OOM Killer） |
| **`SIGINT`** | **2** | 終了 | **可** | キーボードからの割り込み（`Ctrl + C`） |
| **`SIGHUP`** | **1** | 終了 | **可** | 端末切断、またはWebサーバー等の設定ファイル再読み込み |

---

## 2. トラップ処理と強制終了 (`01_trap_and_signals.sh`)

### `trap` コマンドによる Graceful Shutdown
- `trap 'cleanup; exit 0' TERM INT` のように書くことで、シグナル受信時に一時ファイル削除やDB切断などの後始末を確実に実行できます。

### SIGKILL（9）の絶対性と終了コード 137 の秘密
- `SIGKILL(9)` と `SIGSTOP(19)` は、カーネルの仕様により **いかなるプロセスも trap（捕捉）や無視をすることはできません**。
- Linuxの終了ステータス（Exit Status）には以下の計算式があります：
  > **`128 + シグナル番号 = 終了コード`**
  - **SIGKILL (9)** で死んだ場合：`128 + 9 = 137`
  - **SIGTERM (15)** で死んだ場合：`128 + 15 = 143`
- 実務でコンテナが `Exit Code: 137` で落ちていた場合、メモリ不足（OOM Killer）またはタイムアウトでSIGKILLを撃たれたことが即座に判断できます。

## 3. ゾンビプロセスと孤児プロセス (`02_zombie_and_orphan.sh`)

### ゾンビプロセス（Zombie / `<defunct>`）
- **発生原因**:
  - 子プロセスが終了（死亡）した際、OSはプロセステーブルに「終了コード」を残し、状態を **`Z`（Zombie / `<defunct>`）** にします。
  - 親プロセスが `wait()` システムコールを呼んで看取ることで完全消滅しますが、**親が忙しかったりバグで `wait` を呼ばずに放置すると、死んでいるのにプロセステーブルに残り続けます**。
- **影響**:
  - メモリやCPUは消費しませんが、**OSの「PID枠（プロセステーブル）」を占有** します。大量に溜まるとPID枯渇で新しいプロセスが一切起動できなくなります。
- **退治方法**:
  - ゾンビ自身は既に死んでいるため、`kill -9 <ゾンビPID>` を撃っても効きません。
  - **「放置している親プロセスを kill する」** ことで、ゾンビは孤児になり、PID 1に引き取られて即座に消滅します。

### 孤児プロセス（Orphan Process）
- **発生原因**:
  - 子プロセスが実行中に、**親プロセスが先に死んでしまった状態**。
- **OSの救済措置（養子縁組 / re-parenting）**:
  - 親を失ったプロセスは、OSカーネルによって自動的に **最上位プロセス（PID 1: init / systemd / コンテナのメインプロセス）に引き取られ、PPIDが `1` に書き換わります**。

### 実験結果ログ
```text
--- 1. Zombie process (ゾンビプロセス) ---
  [生成時] 親PID: 78 が 子PID: 81 を生成しました（直後に子は終了）
  [外側から観察] プロセスツリーと状態を確認:
root          79      78  0 04:08 pts/1    00:00:00      \_ sleep 3
root          81      79  0 04:08 pts/1    00:00:00      |   \_ [sh] <defunct>

--- 2. Orphan process (孤児プロセス) ---
  [孤児化前] 子プロセスのPID: 85, 親のPID: 84
  [孤児化後] 子プロセスのPID: 85
    PID    PPID STAT CMD
     85       1 S+   sleep 3
```
- パート1では、`sleep 3`（PID 79）の下に `[sh] <defunct>`（PID 81）がぶら下がり、ゾンビが可視化された。
- パート2では、親が死んだ直後に `sleep 3`（PID 85）の親（PPID）が `1` に書き換わった。
