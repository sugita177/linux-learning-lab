# 0-2-05. カーネル空間・ユーザー空間とシステムコール（strace入門）

この節では、Linuxの最重要境界線である **「ユーザー空間」** と **「カーネル空間」** の仕組み、OSへの依頼窓口である **システムコール（System Call）**、および最強のブラックボックス解析ツール **`strace`** の実践的な使い方をハンズオンで解明しました。

---

## 1. ユーザー空間とカーネル空間、システムコールの原理

プログラム（PHP、Nginx、コマンドなど）はハードウェアを直接操作できません。メモリは2つの空間に厳格に分離されています：

1. **ユーザー空間 (User Space)**: 一般のアプリケーションが動く制限された空間。
2. **カーネル空間 (Kernel Space)**: OSの中核（カーネル）が動き、ハードウェアやメモリを直接制御できる特権空間。

アプリケーションが「ファイルを開く」「画面に出力する」「プロセスを変身させる」ときは、カーネルに対して **システムコール（依頼窓口）** を発行して処理を代行してもらいます。

> **`strace` とは？**：
> プログラムとカーネルの間で交わされるシステムコールのやり取りを、ソースコードに手を加えることなく **外側からすべて可視化・傍受するツール** です。

## 2. システムコールの解読と答え合わせ (`01_trace_basic_syscalls.sh`)

これまで学んだすべての知識（FD番号、エラー出力、EOF、終了コード、fork/exec）が、システムコールレベルで1本に繋がりました。

### 正常系：ファイルの読み込みと画面出力
```text
openat(AT_FDCWD, "/tmp/test.txt", O_RDONLY) = 3
read(3, "hello syscall\n", 131072)      = 14
write(1, "hello syscall\n", 14)         = 14
read(3, "", 131072)                     = 0
close(3)                                = 0
+++ exited with 0 +++
```
- **`openat = 3`**: `0`(stdin), `1`(stdout), `2`(stderr) の次に空いている **FD番号 3** がカーネルから払い出された。
- **`read(3, ..., 131072) = 14`**: FD 3 から14バイトをメモリに読み込んだ。
- **`write(1, ..., 14) = 14`**: 読み込んだデータを **FD 1（標準出力）** に書き込んだ（画面に出力された物理的理由）。
- **`read(3, ..., 131072) = 0`**: 戻り値が 0（**EOF: ファイル終端**）。`while read` が終了する原理そのもの。
- **`+++ exited with 0 +++`**: 正常終了ステータス 0 で終了。

---

### 異常系：ファイル未存在と標準エラー出力（FD 2）
```text
openat(AT_FDCWD, "/tmp/missing_config.conf", O_RDONLY) = -1 ENOENT (No such file or directory)
write(2, "cat: ", 5)                    = 5
write(2, "/tmp/missing_config.conf", 24) = 24
write(2, ": No such file or directory", 27) = 27
+++ exited with 1 +++
```
- **`openat = -1 ENOENT`**: 戻り値 -1（失敗）とエラー番号 **`ENOENT`**（Error NO ENTIty: 実体なし）が返る。
- **`write(2, ...)`**: エラーメッセージは、標準出力（1）ではなく **FD 2（標準エラー出力）** に書き込まれる（`2>&1` で合流させる対象）。
- **`+++ exited with 1 +++`**: 失敗を検知して終了ステータス 1 で終了。

---

### プロセスの変身：`execve` システムコール
```text
execve("/usr/bin/ls", ["ls", "/tmp"], 0xffffc6cd26a8 /* 11 vars */) = 0
```
- `fork` で複製された子プロセスが、自身のメモリをバイナリ（`/usr/bin/ls`）、引数リスト、環境変数で丸ごと上書きして **別のプログラムに変身（exec）** した瞬間。

## 3. ★実務での最強活用パターン

### 1. 「設定ファイルが見つからない」エラーの即時特定
アプリがどこを探して落ちたのか分からないとき、ソースを追わずに一発で特定できます：
```bash
strace -e trace=openat <実行コマンド> 2>&1 | grep ENOENT
```

### 2. 本番でハング（応答停止）したプロセスの調査
CPU使用率が上がらず処理が止まっているプロセスのPIDを指定して盗み見します：
```bash
strace -p <PID>
```
（※ロック待ち、通信待ち、特定のシステムコールで止まっている箇所がリアルタイムに表示されます）
